# 2026-11-22 — Phase 6: mobile API v1 polish

The endpoints existed. This pass made them one contract, turning up three
live defects.

- **The envelope only covered our own errors.** Laravel answered an expired
  token with `{"message":"Unauthenticated."}` and validation with
  `{message, errors}` — neither carrying `success`, the flag both apps branch
  on. `ApiExceptionRenderer` maps every throwable on `api/*` into
  `ApiResponse`'s shape. 404 stopped naming the model class and route path;
  404/405 stopped returning a stack trace. Each failure carries a stable
  `errors.reason`, as `message` is display text.
- **`per_page=-5` returned a 500** — it reached MySQL as `offset 0` with no
  limit, and the SQL error reached the client. `100000` was honoured; `0` fell
  through to Eloquent's 15, not the documented 20. `PerPage` clamps 1–100,
  default 20, treating anything unusable as unasked rather than an error: a
  shipped build cannot be fixed today. All seven lists read it; `meta` gained
  `from`, `to`, `has_more`.
- **`user.regions[]` had been `[]` since Phase 2**, so no telecaller learnt
  its own territories. Filled through the Regions contract, resolved from the
  container: a resource takes no constructor injection, and both `login` and
  `me` must always carry it.
- **A token outlived its account.** `canSignIn()` was consulted only at
  login, so deactivating an MR — or moving their role — left their token able
  to file visits. Route files group on `api.auth` instead of `auth:sanctum`;
  it re-checks the account and the token's role ability per request.
- **Policies** per module, from a new `policies()` hook on
  `ModuleServiceProvider`. Services delegate row checks to them, so one rule
  renders 403 in the panel and 404 on the API, where confirming a row exists
  would leak it. `CallLogPolicy::update` and `MessagePolicy::markRead` keep no
  admin bypass.
- 102 smoke checks green (`tests/smoke/phase6-api.sh`): envelope, the clamp
  on every list, 403-vs-404, stale tokens, Phases 3–5.

# 2026-11-22 — Phase 5: messaging, telecaller → MR (no Firebase)

- `messages` with optional `person_id` / `call_log_id` context, both
  `nullOnDelete`: losing the context must not delete what someone said.
- Read state is a single nullable `read_at`. The planned schema had an
  `is_read` flag beside it; two columns that must agree eventually do not, so
  the flag is derived in the API resource instead. A sender cannot set it —
  a message starts unread by definition, and only the recipient may mark it.
- The poll is the design constraint. `unread-count` is one indexed COUNT and
  nothing more, with `(to_user_id, read_at)` so it is answered from the index.
  Marking is idempotent, so a retry on a flaky connection is not an error,
  and `read-all` returns how many actually changed.
- Recipients: MRs covering a region the sender covers, **plus the MR assigned
  to the person being written about**. That second clause matters — a doctor
  in region A can be assigned a rep whose own region is B, and the common
  flow is "I spoke to this doctor, their rep should visit". Refusing that
  over a region mismatch would be a dead end. `recipientsFor` backs both the
  picker and the validation rule, so the two cannot drift apart.
- The rule is re-checked in `sendAs`, not only in the request: it is the
  module's rule, and a later caller must not be able to route around it.
- Panel scope is **either party** — unlike calls, a message has two owners.
  The participant clause is wrapped in its own closure, or the OR would
  escape any filter sitting beside it.
- Added `UserService::activeOfRoleInRegions`, so Messages can ask "who works
  here?" through a contract instead of touching the users table.
- Found that Cuba title-cases a `.card-header h5`, which re-cased a subject
  the telecaller typed. Its `:not(.mb-0), :not(.m-0)` opt-out is a selector
  list, so adding one class never escapes it — noted in `ui-cuba.md`.
- 72 smoke checks green; Phases 3 and 4 unchanged at 62, 76 and 35.

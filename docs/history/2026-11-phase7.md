# 2026-11-22 — Phase 7: dashboards

One screen, one template, every role — and the last module boundary closed.

- **Which cards you see is the modules' decision.** The service asks each
  module's policy `viewAny` and builds only what comes back: six tiles and
  four charts for an admin, four and two for a telecaller. No role test in
  the controller or the Blade, no queries for a card nobody may see — and the
  Phase 6 policies now have the caller they were written for.
- **Scope stays where the rule lives.** Every read is a `…ForUser` method. A
  telecaller covering a quiet region gets zeros and an empty-state card,
  never another region's numbers.
- **Attendance had no `region_scope`.** Visits and Persons both did; its
  filters took only a single `region_id`, so a scoped viewer would have
  charted every rep in the company. Added, same contract as its siblings.
- New reads: daily trends on visits, calls and attendance, visits per rep,
  and two counts the tiles needed — persons (clamped like the list, so tile
  and screen agree) and active reps in a role, since "3 of 8 checked in"
  cannot come from attendance rows: a rep who never checked in has no row.
  `countsByMr` groups by name, not id, or two reps sharing a name would
  overwrite each other in a name-keyed result and one would vanish.
- Charts use the committed ApexCharts 3.46.0; Cuba's `chart-custom.js` beside
  it is demo data on demo element ids and is not loaded. Donut colours come
  from `CallStatus::badge()`. The y axis takes its tick count from the data:
  left alone, Apex put four ticks on a chart whose max was 1, which the
  rounding formatter printed 2, 2, 1, 1, 0.
- **The dashboard moved into its module.** `routes/web.php` now registers no
  routes and `app/Http/Controllers` holds only the base `Controller`, closing
  an open item carried since Phase 0.
- 56 panel checks green (`tests/smoke/phase7-dashboard.sh`), Phase 6's 102
  API checks still green, both dashboards rendered in Chromium with no
  console errors.

# 2026-11-22 — Phase 9: the MR Flutter app

Repo: `prishapharmamrapp`, branch `claude/happy-ramanujan-zthjt1`.

- **What was there did not compile** — 4,548 analyzer issues. A generic-CRM
  scaffold (customers, orders, products) on endpoints deleted in Phase 2;
  `app_router.dart` held placeholders shadowing the real screens,
  `authProvider` was declared twice, and `GoRoute` was given a
  `parentBuilder` that is not a parameter. Stripped, not patched.
- **Four screens** on the Phase 6 contract: login, geo check-in/out, a
  geo-stamped visit form with history, and the inbox with its polled badge.
  One feature per directory — `domain`, `data`, `state`, `ui` — on Riverpod,
  not ProKit's MobX.
- `ApiClient` decodes the envelope once and throws a typed `ApiFailure`
  carrying the stable `errors.reason`, so no screen sees Dio, a status code
  or prose to parse. `account_inactive` and `role_changed` clear the token
  and drop to login; `forbidden` does not.
- **Material has left the Flutter SDK.** `package:flutter/material` is
  deprecated after 3.47 for `package:material_ui`, which defines its own
  `TextTheme`/`ThemeData` — not re-exports, so mixing them will not compile.
  `lib/` uses material_ui throughout; the UI deps moved to migrated
  versions (google_fonts 9, go_router 18, riverpod 3).
- **Three bugs that only bite on a device:** `INTERNET` was in the debug
  manifest only, so a release build could not reach the API; no location
  permissions, for a wholly geo-stamped feature; and no iOS
  `NSLocationWhenInUseUsageDescription`, which crashes on first use.
- Verified by a clean `flutter analyze` and 40 tests. Model tests use
  fixtures captured from the live API, client tests its real 401/403/409/422
  bodies — so a rename fails here, not on a rep's phone. Golden renders
  caught a 42px overflow and a stretched logo.
- **Not done:** no device here, so nothing ran on real hardware.
  `applicationId` is still `com.example.mr_app`; the token is in
  `SharedPreferences`, not the Keystore.

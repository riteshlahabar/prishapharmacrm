# 2026-11-21 — Phase 2: masters (regions, persons)

- `regions` (name, code uniq, is_active) plus `telecaller_region`. Decided the
  open question in regions.md: an MR covers **one** region on `users.region_id`,
  a telecaller covers **many** through the pivot. A rep travels a territory; a
  phone list can be widened at any time.
- `RegionAssignmentService` hides that asymmetry behind one `assign()`, so the
  Users module never branches on role to save a region. The user form posts
  `region_ids[]` either way and the select is `multiple` only for telecallers.
- The Phase 1 `users.region_id` FK finally went on, `nullOnDelete`: losing a
  region must not delete the people working it. `RegionService::delete` refuses
  while anyone still points at a region and tells you who.
- `customers` → `persons` by **rename**, not create-and-drop, so a live
  deployment keeps its rows — verified by rolling back, inserting legacy rows
  and re-running. Converted rows land as `type=doctor` and need re-typing.
- `down()` had a real bug: MySQL uses the `(region_id, type)` index to satisfy
  the region FK and refuses to drop it first. Constraints now go before the
  index, which goes before the columns.
- `PersonService::paginateForUser` clamps the list to the regions a non-admin
  covers. The clamp is in the service, not the controller, so no caller can
  forget it; an empty region list yields nothing rather than everything.
- Specialization is doctors-only and nulled server-side on a type change.
  Assignee rules check the target's role, so a telecaller id cannot be posted
  into the MR field.
- `products`, `orders` and the generic-CRM controllers, models, requests,
  views, routes and migrations are gone; `app/Models` no longer exists. The
  flash partial moved to `resources/views/partials` so Regions and Persons do
  not reach into the Users view namespace.
- Smoke suite grew to 67 checks, green on a fresh `migrate:fresh --seed`.

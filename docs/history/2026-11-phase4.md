# 2026-11-22 — Phase 4: telecaller backend (calls, person queue)

- `call_logs` with a `CallStatus` enum (interested, not_interested, callback,
  not_reachable, converted). No uniqueness: ringing the same person twice in a
  day is ordinary work, and the record of attempts is the point.
- `called_at` is server-set, like the attendance stamps, so a device cannot
  back-date work. `telecaller_id` comes from the token.
- The call-back rule is the one that needed care. Only `callback` carries a
  `follow_up_at`, it must be in the future, and the request **refuses** a date
  on any other status — otherwise a row would sit in the queue with nothing
  that could ever close it. Three things close one: logging a newer call on
  that person, moving the status off `callback`, or `follow-up-done`, which
  clears it without inventing a call that never happened.
- Added `follow_up_done_at`, which the planned schema did not have. Without it
  the queue has to infer "already handled" from a later call, and an explicit
  close is both cheaper to query and honest about what happened.
- `person_id` validates against the **caller's own regions**, not merely
  `exists`. The app only ever shows a scoped queue, so an out-of-region id is
  a tampered payload; a telecaller with no regions can call nobody.
- Scope here is the **caller, not the territory** — deliberately unlike
  visits. Two telecallers can share a region; their notes stay their own.
  `paginateForUser`, `summaryForUser` and `findForUser` clamp on
  `telecaller_id`, and a colleague's call reads as 404.
- `/api/v1/persons` shipped early (persons.md had it at Phase 6) because a
  call queue needs it. One handler, scoped by role: telecaller → regions,
  MR → own assignments. For a telecaller each row carries `last_call`, read
  through the Calls **service contract** in one query, so Persons never
  touches `call_logs`.
- 76 smoke checks plus 35 panel checks, which sign a telecaller in and prove
  the list, the detail, the delete and the sidebar are all narrowed.
